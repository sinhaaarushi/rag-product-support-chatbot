# Contributing to this repo

This file is the contract for anyone touching this codebase — human or AI. It
exists so that reviews are boring, git log reads like prose, and no one has to
relearn the local conventions every week.

If you're an AI coding assistant: read this once at the start of a session and
hold to it. Don't link to it in commit messages or add trailers referencing it.

---

## 1. Code style

Python, 3.10+. Lint and format with `ruff` (config in `pyproject.toml`).

### Names

- Prefer names that carry domain meaning: `document_storage_key`, `chunk_overlap`,
  `retrieval_candidates`, `embedding_dimension`.
- Avoid low-information names in non-trivial scopes: `data`, `out`, `tmp`,
  `value`, `result` (unless it actually is the result being returned),
  single letters outside of short comprehensions.
- Booleans read as propositions: `is_offline`, `has_sources`, `enforce_pattern`,
  not `offline_flag` or `flag_enforce`.

### Comments

- Explain **why**, not what. The code already says what.
- Good: "Flan-T5's encoder is 512 tokens; truncate at the tokenizer boundary
  so the model sees a valid window."
- Bad: "Call the tokenizer."
- Module and non-trivial function docstrings earn their keep when they record
  trade-offs, invariants, or upgrade paths. Don't docstring every one-liner.
- If you leave a `TODO`, sign it and give it a trigger condition
  (`# TODO(aarushi): swap to sentence-aware chunker when recall drops below X`).

### Shape of code

- One logical job per function. If the name needs "and" to describe it, split it.
- Functions that fit on a screen are easier to review. When they can't, the
  split usually wants to be on an I/O boundary.
- Avoid abstractions introduced "for the future." Add them when the second
  caller appears.

## 2. Structure

The project is organised by subsystem, not by layer:

```
Ingestion/      PDF → text
Processing/     text → chunks
Embeddings/     text → vectors
VectorStore/    FAISS index + metadata persistence
Retrieval/      query → ranked chunks
LLM/            grounded answer generation
App/            orchestration + Streamlit dashboard
Utils/          cross-cutting helpers (logging, backups)
pipeline.py     end-to-end indexing entry points
config.py       single source of runtime configuration
scripts/        standalone CLI entry points (download models, rebuild, smoke)
tests/          pytest suite
Data/           local-only artefacts (gitignored beyond placeholders)
```

Keep modules cohesive. If `Retrieval/retriever.py` starts handling prompt
construction, that belongs in `LLM/` instead.

---

## 3. Configuration and paths

- Everything configurable lives in `config.py`, read from env vars with
  sensible defaults. New knobs go there, not scattered around.
- No absolute user paths (`C:\Users\...`) in committed code.
- Document loaders, indexers, and scripts route through `config.DOCUMENTS_DIR`
  and `config.VECTOR_STORE_DIR`. Never hardcode `Data/...` elsewhere.

---

## 4. Error handling

- Raise with context: include the offending path, value, or state.
  `raise FileNotFoundError(f"PDF not found: {path}")`, not a bare message.
- The dashboard is the only place where exceptions get swallowed into a UI
  message. Library code lets them propagate.
- Don't catch `Exception` just to re-raise. If you need a wider net, document
  why in a comment.

---

## 5. Testing

- New behaviour ships with a test that fails without it. Bug fixes ship with
  a regression test.
- Unit tests mock the heavy bits (embedding model, FAISS, LLM). The full
  pipeline is exercised manually via `scripts/rebuild_index.py` and
  `scripts/sample_query.py`.
- Run `pytest` before committing. Run `ruff check .` and
  `ruff format --check .` too; CI runs both.

---

## 6. Security and data boundaries

- No external LLM APIs. Ever. The project ships offline-only by default.
- `Data/documents/`, `Data/vector_store/`, `Data/logs/`, `Data/backups/` are
  local-only by policy and listed in `.gitignore`.
- `.env`, real API keys, model paths tied to a specific machine, and absolute
  Windows user paths never get committed.
- FAISS indexes, pickled metadata, and model weights stay out of git.

---

## 7. Commits

See the global commit guidelines (maintained outside this repo). Short version:

- Imperative mood, lowercase subject, no trailing period, optional scope prefix
  (`loader:`, `retriever:`, `scripts:`, `ci:`, `docs:`).
- One logical change per commit. If a diff covers two unrelated things, split.
- Body only when the *why* isn't obvious from the diff.
- No AI attribution, no "Generated by ...", no `Made-with:` trailers,
  no `Co-authored-by: <tool>`.
- Never `--force` push or amend already-pushed commits without explicit
  confirmation in the same turn.

---

## 8. What this project is *not*

- It's not a multi-tenant service. Auth is a single optional API key.
- It's not a training pipeline. All models are pre-trained, loaded offline.
- It's not a distributed vector store. FAISS flat index on a single machine
  is the current answer; revisit only if the index crosses a few million
  vectors or latency regresses.

If the scope changes, update this file first, then the code.
